Click to toggle

Composition: The fleet package is designed in ABS as a bundle of Product-Units. Odoo records only the individual PU line items on sale.order.line.

PU CategoryOdoo product.template.typeInvoice PolicyAccounting
Physical'product' (stockable)Delivered quantitiesRevenue on delivery
Contract (deposit)'service' + liability accountPrepaidLiability, not revenue
Contract (warranty)'service'PrepaidDeferred revenue

Extended sale.order fields: x_channel_partner_id, x_sales_rep_id, x_outlet_id (points to ov.outlet). These persist through the full order lifecycle for channel attribution and analytics.

Product-Unit 5 Dimensions: Identity, Value, Context, Obligations, and Costs are stored on product.template custom fields. ABS holds the canonical PU definition; Odoo handles commercial execution.

Possible Outcomes

Approved
Proforma is cleared. Sales rep can now send the PI to the customer. Payment collection is authorized. This is the current state.
Rejected
Manager declines the deal entirely. Order returns to the sales rep with a reason (e.g. "margins too thin", "customer credit risk"). The quotation can be revised and resubmitted or cancelled.
Revision Requested
Manager asks for specific changes before approving (e.g. "reduce discount to 3%", "add delivery charge", "extend deposit term to 24mo"). Returns to Step 2 for editing.

Approval workflows in Odoo

Click to toggle

Odoo doesn't have a built-in proforma approval workflow out of the box. You'd implement this via one of these approaches:

  1. Odoo Approvals module (approvals): Create an approval request type "Proforma Invoice" with multi-level rules based on amount thresholds. The approval request links to the sale.order via a reference field.
  2. Custom state on sale.order: Add a custom state 'pending_approval' between 'sale' and the proforma send action. Use ir.rule to restrict who can transition past this state.
  3. Studio workflow: Use Odoo Studio to add an approval step with email notifications triggered by mail.activity assigned to the appropriate manager.

Recommended approach: Option 1 (Approvals module) is cleanest. The flow becomes:

  1. Sales rep confirms order → sale.order.state = 'sale'
  2. Sales rep clicks "Request Approval" → creates approval.request linked to SO
  3. Manager receives notification, reviews the order and proforma PDF
  4. Manager approves/rejects/requests changes on the approval.request
  5. On approval, a flag (x_pi_approved = True) unlocks the "Send Proforma to Customer" button
  6. On rejection, sales rep is notified and can revise the quotation (cancel → re-quote) or escalate
